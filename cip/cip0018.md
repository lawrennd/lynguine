## Summary

Two opt-in, generic directory-source behaviours so inherited catalogs keep one store and one discovery set:

1. **Bind** specs that allocate by `glob` (no `filename`) to `inherit.directory`, the same way filename specs already bind.
2. **Exclude** matched paths with an explicit glob list on the source entry, so view configs nested in a discovered tree are not rows of that catalog.

This CIP implements [REQ-000F](../requirements/req000F_inherited-directory-sources.md). It does not teach lynguine about `_referia.yml`, `today/`, or referia overviews. Downstream consumer: referia CIP-001C.

## Motivation

Filename sources with `directory: .` already resolve under `inherit.directory` (`_bind_spec_directory`, `test_from_file_inherit_binds_parent_data_directory`). Directory sources used by catalogs look like:

```yaml
input:
  type: yaml_directory
  source:
    - directory: .
      glob: "**/_referia.yml"
      recursive: true
      include_start_directory: false
```

Those entries have `directory` and `glob`, not `filename`. Bind currently skips them. A child that inherits the catalog therefore glob-walks **its own** directory. Discovery is empty or wrong; the child is not a view over the parent store.

Separately, `include_start_directory: false` omits the start directory's own file but still matches nested `today/_referia.yml` and `year/_referia.yml`. Callers can enumerate work folders as separate `source` entries, but a catalog that auto-picks new top-level directories needs a generic omit. A leaf `discover: false` key is rejected: it would teach infrastructure about application overviews.

## Detailed Description

### 1. Bind directory sources on inherit

`Interface._bind_spec_directory` rewrites relative `directory` only when `"filename" in spec`. Change the gate to path-allocating specs:

```python
is_path_spec = "glob" in spec or ("filename" in spec and "type" in spec)
```

``store_fields`` uses ``filename`` as a column name mapping, not a path.
Binding any dict that merely contains ``filename`` rewrote
``directory: sourceDirectory`` into ``{inherit}/sourceDirectory`` and broke
inherited catalogs. Require ``type`` with ``filename``, or ``glob``.

When true, apply the existing rewrite:

- missing / empty `directory` → `inherit.directory`
- relative `directory` → `normpath(join(inherit.directory, expanded))`
- absolute `directory` → unchanged (still confined at access)

Recursion already walks nested dicts and lists, so `input.source[]` entries with `glob` are reached.

Do **not** rewrite a bare `directory` key that has neither `filename` nor `glob`. That would over-bind unrelated mappings.

Output with `filename: catalog-scores.yml` and `directory: ./info` already binds. This CIP does not change that path; tests should still assert the child writes the parent's score file when inherit is writable.

### 2. Source `exclude` globs

On each directory `source` entry (and optionally top-level `details`, source wins):

```yaml
source:
  - directory: .
    glob: "**/_referia.yml"
    recursive: true
    include_start_directory: false
    exclude:
      - today/**
      - year/**
```

| Key | Default | Effect |
|-----|---------|--------|
| `exclude` | absent / `[]` | After glob, `regexp`, and `include_start_directory`, drop matches whose path **relative to the source directory** matches any pattern (`fnmatch` / `Path.match` semantics, `**` allowed). |

- Patterns are relative to that source's resolved `directory`, not cwd.
- Matching is on the confined relative path using POSIX separators, so configs are portable.
- Empty exclude / absent key: today's match set.
- Log at debug: pattern list and how many paths were dropped.
- Apply in the shared `read_directory` path so all `*_directory` readers benefit (same as CIP-000F `recursive` / `fields` / `include_start_directory`).
- No default excludes. No special-case of `_referia.yml` or directory names.

`include_start_directory: false` remains necessary to omit the file in `.` itself. Exclude is the extra nested-view rule.

### Alternatives considered

| Approach | Decision |
|----------|----------|
| Bind every nested `directory` key | Rejected — over-binds unrelated mappings |
| Application rewrites `.` to an absolute OneDrive path in the child | Rejected — implicit, host-specific, forks infrastructure |
| Enumerate work directories as `source` entries (no exclude) | Valid YAML alternative; insufficient when auto-discovery of new top-level folders is required |
| Leaf `discover: false` | Rejected — teaches lynguine about referia overviews |
| Always skip directories named `today` / `year` | Rejected — implicit; surprises other trees |

### Downstream contract for referia CIP-001C

A sibling `today/_referia.yml` that inherits the catalog with `directory: ../` must:

- Discover the same descendant configs the parent would (from the catalog root, not from `today/`)
- Share `info/catalog-scores.yml` (filename bind already does this; keep a regression test)
- Omit `today/**` and `year/**` from catalog rows **because the parent source lists those excludes**, not because lynguine knows the view names

Referia's inherit opt-in (`inherit.reuse`) is **not** this CIP.

## Implementation Plan

1. **Bind glob specs**
   - Extend `_bind_spec_directory` as above.
   - Tests: inherited `yaml_directory` `source[].directory: .` resolves to parent; child under `today/` discovers parent files; filename bind unchanged; absolute directories unchanged.

2. **Exclude**
   - Thread `exclude` through `read_directory`.
   - Tests: listed globs omitted; unlisted nested files kept; default unchanged; works with `include_start_directory: false`; confinement still applied to kept paths.

3. **Docs**
   - Directory-of-Files: inherit bind for glob specs; `exclude` alongside `recursive` / `fields` / `include_start_directory`.
   - Release note: both opt-in.

## Backward Compatibility

- Filename-only bind unchanged.
- Absent `exclude` preserves current match sets.
- Configs that already enumerated work directories keep working; they may adopt `exclude` later.

## Testing Strategy

- Unit tests in lynguine only (tmp_path trees; no referia fixtures).
- Bind: parent catalog YAML + child inherit; glob source `.` → parent realpath; `from_flow` reads parent files.
- Exclude: `a/work.yml` kept, `today/x.yml` dropped for `exclude: [today/**]`; start-dir file still controlled only by `include_start_directory`.
- CIP-000A: excluded paths are not read; kept paths still confined.
- Regression: `test_from_file_inherit_binds_parent_data_directory`, `include_start_directory` tests.
