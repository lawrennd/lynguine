# CIP-0015: Declared store encodings (gzip YAML, then parquet)

## Summary

Extend YAML and JSON Access IO so a store can round-trip through **gzip** (stdlib) without changing logical `type: yaml` / `type: json`. Compression is declared by filename suffix (`.yml.gz`, `.yaml.gz`, `.json.gz`) and/or a store key `compress: gzip`. Add a small `store_stat` helper that returns path, exists, mtime, size, and codec **without loading the table**.

Addresses [REQ-000E](../requirements/req000E_compressed-yaml-stores.md). Referia dialogue caches and packed embedding YAML are the first consumers (referia CIP-0015 / CIP-0016). Gzip YAML is v1. Binary tables are the same named-store contract with `type: parquet` (phase 2), not a second cache system and not undeclared npy sidecars. This CIP does not replace named cache vs output policy.

## Motivation

`read_yaml_file` / `write_yaml_file` always use text `open()`. Dialogue extract/embed will write:

- chunk `units` and exploded `text` (duplicated grain if both cache and output persist)
- LLM `extraction_payload`
- embedding vectors as YAML lists of floats (the real disk killer)
- packed `records.yml` arrays and `document_distance.yml` matrices

Uncompressed YAML of float lists will thrash disks. Gzip of YAML is the boring, suitable compressor: the logical document stays YAML; git-friendly uncompressed files remain the default for small tables.

CIP-0010 / CIP-0014 reshape (wide flatten, explode, pack) do not own encoding. Keep encoding in IO.

## Detailed Description

### Explicit, not magic

- Logical type stays `yaml` or `json`.
- On-disk name is the actual file: `filename: phrases.yml.gz`.
- `compress: gzip` is allowed as a redundant declaration. If `compress: gzip` and the filename does **not** end in `.gz`, raise: do not silently rewrite `phrases.yml` → `phrases.yml.gz`.
- A `.yml` file is never gunzipped on a magic-byte sniff. If the file is gzip but named `.yml`, fail with an explicit error naming the suffix.
- Uncompressed configs unchanged.

### IO placement

Wrap `read_yaml_file` / `write_yaml_file` (and JSON equivalents) so `extract_full_filename` still confines the path (CIP-000A). Use `gzip.open` from the stdlib. Default gzip level 6 (or document 9 for bulky embedding stores via `compress_level:`).

`extract_file_type("phrases.yml.gz")` must resolve to yaml, not a new type. Strip one compression suffix, then the logical suffix.

`type: yaml` + `.yml.gz` is enough. Do **not** add `type: yaml_gz`.

### `store_stat` (no table load)

Return a dict / mapping suitable as a **parameter** field (one per named store, not per row):

```yaml
path: /abs/info/_extract_cache.yml.gz
exists: true
mtime: "2026-10-21T09:14:00+01:00"
size_bytes: 184320
codec: gzip          # or null
logical_type: yaml
role: cache          # from the flow key, if known
```

If the file is absent: `exists: false`, other fields null/0, no exception (the flow already fails later if the store is required input). Referia uses this for cache visibility (referia CIP-0017). Lynguine does not render UI.

### Encoding ladder (same named store)

Cache/output/input are **roles**. `type:` is the on-disk encoding. Gzip YAML is v1 of this CIP. Binary is not a second cache mechanism — it is another `type` on the same store.

| Encoding | When | Example |
|----------|------|---------|
| `type: yaml` (plain) | Small, diffable, human-edited | `documents.yml`, `constants.yml`, review notes |
| `type: yaml` + `.yml.gz` | Text-heavy regenerable cache | LLM `extraction_payload`, optional chunk `units` |
| `type: parquet` | Mixed table whose **numeric columns** dominate size | phrase rows + `embedding`; `scores` (`responsibilities`); `document_distance` matrices |
| `type: npy` / `npz` (single array) | One homogeneous ndarray that is a **column**, composed with a table via existing `hstack` | `embeddings.npy` aligned on `phrase_id` |

Choose by **column kind**, not by the word cache:

- LLM payloads, chunk text, quotes → text; gzip YAML is enough (and grep-able if you unzip).
- Embedding vectors, R, EMD, MDS, packed `embeddings` cell → binary. Gzip-of-YAML-floats still explodes: each float becomes ~12–20 ASCII bytes before gzip, and parse time dominates.
- Packed one-row corpus: parquet (list/array columns) or yaml catalogue **hstack** an `npy` of shape `(n, d)`.

**Do not** use pickle as an analysis store (version-fragile, not a table, CIP-000A untrusted paths). **Do not** drop an undeclared `embeddings.npy` beside a YAML file; if npy is used it is a named store (or an `hstack` specification) with its own `type` and `index`.

#### Parquet (standard binary *table*)

`CustomDataFrame.to_parquet` already exists; it is **not** wired through `read_data` / `write_data`. Integration is the same switch as `yaml`/`csv`:

```yaml
output:
  type: parquet
  filename: phrases.parquet
  directory: ../info
  index: phrase_id
  columns:
    - phrase
    - kind
    - embedding
```

Optional extra `lynguine[parquet]` → `pyarrow`. Embeddings as Arrow `list<float32>` (or a fixed-size list), not pickle-in-an-object-column. `store_stat.logical_type: parquet`, `codec: snappy` (or zstd). Referia CIP-0017 shows this the same way as gzip YAML.

This is **phase 2 of this CIP** (or a thin follow-on CIP if gzip should land first). Same REQ-000E spirit: declared encoding, round-trip to the same table, no sidecar converter.

#### npy as a column store (only if parquet list columns are not enough)

One file = one ndarray. Not a DataFrame. Compose with `hstack`:

```yaml
output:
  type: hstack
  specifications:
    - type: yaml
      filename: phrases_meta.yml
      index: phrase_id
    - type: npy
      filename: embeddings.npy
      index: phrase_id
      column: embedding
      dtype: float32
      shape:
        - null    # n rows from index
        - 3072
```

Harder than parquet (shape/index alignment tests). Use only when a single dense matrix is the artefact. Not v1.

**Format stability.** `.npy` is a documented ndarray layout (magic + format version 1.0/2.0/3.0 + dtype/shape header + raw bytes). Numeric dtypes (`float32`, `float64`, `int64`, …) round-trip across NumPy versions; that is not pickle’s class-layout fragility. **Forbid `dtype=object`:** NumPy stores object arrays by pickling, which reintroduces the problem. Declare `dtype` in the store (as above). Exotic dtypes (`bfloat16`) are allowed only when both writer and reader name them; default analysis arrays are `float32`.

**JAX (and other array libraries).** There is no `type: jax`. JAX arrays are host `numpy` on the way in and out of Access (`np.asarray(x)` / `jnp.asarray(x)`). The store remains `type: npy` with a declared `dtype` and `shape`. That is the interchange for a single dense artefact (embedding matrix, distance matrix). Nested pytrees / optimiser state are **not** this store — those belong in a checkpoint format (Orbax, etc.), not an analysis column. PyTorch tensors follow the same rule: convert to numpy, same `npy` file.

### What this is not

- Not LLMManager / `diskcache` (API cost cache).
- Not a new compute mode.
- Not zstd/xz **on YAML** in v1 (may be a later declared codec with the same `compress:` key; parquet has its own codecs).
- Not “auto-compress caches over N MB”. Size policy lives in the application config (choose `yaml` vs `yaml.gz` vs `parquet`).
- Not pickle, hdf5, or zarr in this CIP.

### Alternatives rejected

- **Always gzip cache** — small review caches should stay diffable text.
- **Sniff gzip magic on every `.yml`** — hidden encoding; breaks editors and git.
- **Application-level `gzip` compute** — encoding belongs in Access IO, same as csv/xlsx.

## Implementation Plan

1. Suffix stripping in file-type detection (`.yml.gz` → yaml).
2. gzip wrap on yaml/json read and write; round-trip tests (mapping and sequence YAML).
3. `compress:` / `compress_level:` validation (mismatch with suffix is an error).
4. `store_stat` helper + tests (missing file, plain yml, yml.gz).
5. Document in Access IO docstring; CIP-0014 pack/explode examples may use `.yml.gz` for embeddings.
6. **Phase 2:** `type: parquet` in `read_data` / `write_data`; extra `lynguine[parquet]`; round-trip a phrase table with a float32 list column; `store_stat` for `.parquet`.

## Backward Compatibility

Default remains uncompressed `.yml` / `.json`. Existing flows unchanged. New files only when the config names a `.gz` (or `compress:`) path.

## Testing Strategy

- Round-trip a three-row phrase table with a float list column; gzip file smaller than plain YAML; loaded frame equal.
- Refuse `.yml` whose bytes are gzip.
- Refuse `compress: gzip` with a non-`.gz` filename.
- `store_stat` on missing, plain, and gzip files (mtime timezone-aware ISO).
- CIP-000A: confined paths still apply.
