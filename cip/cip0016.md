# CIP-0016: Demand-driven Liquid mapping

## Summary

`CustomDataFrame.liquid_to_value` currently calls `mapping()` whenever kwargs are omitted. `mapping()` copies **every** name→value on the current row into a dict, including packed list columns such as `embeddings`. Referia web evaluates each `viewer:` Liquid entry independently, so a page with four captions rebuilds that dict four times.

That contract was written for Jupyter review fields (`{{Title}}`, `{{Comment}}`). It is the wrong namespace for CIP-0014 packed corpus rows. This CIP makes Liquid fetch **only the identifiers the template names**. `mapping()` with no arguments stays the full-row dict for callers that asked for it. Debug logs must not stringify cell values.

Addresses [REQ-0002](../requirements/req0002_predictable-architecture.md). Pack/gzip (CIP-0014 / CIP-0015) stay as they are; they own grain and encoding, not template binding.

## Motivation

Measured on referia `dialogue-analysis/draghi-competitiveness/04_distance` (one packed `Name: corpus` row, 77 columns, `embeddings` ≈ 2.3 MB as JSON):

| Call | Time |
|---|---|
| `from_flow` / `load_flows(reload=True)` | ~3.5 s |
| `mapping()` (all columns, including embeddings) | **~2.3 s** |
| `get_row_data()` (same cells, no value repr) | ~0.95 s |
| `liquid_to_value("{{ store_status.output.path }}")` with fresh `mapping()` | ~2.6 s |
| same template with a reused mapping | **~0.001 s** |
| four Liquid viewers + Compute chrome | ~8 s |
| PlotlyFigure of stored specs | ~0 s |
| HTTP GET of the already-loaded page | ~10 s |

The 04 `_referia.yml` Liquid only names `store_status` and `selected_doc`. The EMD primer and plot captions are static. Compute still needs `embeddings` on the row (`row_args`). The YAML did not ask Liquid to see those arrays.

The extra 1.4 s of `mapping()` over `get_row_data()` is eager f-string interpolation in debug logs:

```python
log.debug(f"Setting \"{name}\" column of format to \"{value}\".")
```

That `f"...{value}..."` runs even when the logger is at WARNING.

This is not a display-layout problem (`side_by_side` vs `inline_list`). `inline_list` is worse: it walks every working index. HTML viewer chrome still copies the row via `get_row_data()`. Gzip (CIP-0015) shrinks disk, not this RAM/render path.

## Detailed Description

### Current contract (implicit full row)

`view_to_value` / `liquid_to_value` (`lynguine/assess/data.py`):

- If `kwargs is None` or `{}`, call `self.mapping()`.
- `mapping()` walks `_name_column_map`, `set_column` + `get_value` for each name, `remove_nan`, return a dict.
- Liquid `render(**kwargs)` then receives every cell.

Jupyter widgets rely on that so a template can mention any mapped column without declaring inputs. Scalar review fields made that cheap. CIP-0014 `pack` puts phrase lists, embedding matrices, and Plotly JSON on the same row as `store_status`. Treating those as Liquid locals is implicit and expensive.

Tenet *explicit-infrastructure*: a template that writes `{{ store_status.output.path }}` should cause a read of `store_status`, not of `embeddings`.

### Proposed contract

**A. Liquid is demand-driven.** When `liquid_to_value` is not given kwargs, bind only root identifiers that appear in the template (and in `local`). `{{ store_status.output.path }}` → fetch `store_status`. `{% if selected_doc %}` → fetch `selected_doc`. Identifiers that are not columns stay absent unless supplied in `local` (today: `rows` for referia `inline_list`).

**B. `mapping()` remains explicit full-row.** Callers that invoke `mapping()` with no name list still get every mapped column. Jupyter forms keep that API. Do not silently drop large cells from `mapping()`. Size heuristics are magic.

**C. Optional subset API.** `mapping(names=["store_status", "selected_doc"])` (or `mapping={"store_status": "store_status", ...}` as today) fetches only those names. Liquid uses this after identifier extraction.

**D. Cache for the current index.** Several sibling Liquid blocks on one HTMX GET must not rebuild the same subset. Cache key: `(get_index(), frozenset(names))`. Invalidate on `set_index`, `set_value`, and `from_flow`. Document that the cache is a per-object render memo, not a second data store.

**E. Debug logs never interpolate cell values.** Use lazy `%s` for names/types only, e.g. `log.debug("mapping %s type=%s", name, type(value).__name__)`. No `f"{value}"`. Same rule anywhere `mapping` / `get_value` logs a cell.

**F. Fallback is explicit.** If identifier extraction fails (parse error, unsupported tag that needs the whole context), call full `mapping()`, log at WARNING with the reason, and render. Do not guess a byte-size cutoff.

### Identifier extraction

Use the existing Liquid environment (`self.compute._liquid_env`) to parse the template and collect root variable names from the parse tree. Dot paths contribute only the first segment. Tests must lock:

- `{{ store_status.output.path }}` → `{"store_status"}`
- `{% if selected_doc %}...{% endif %}` → `{"selected_doc"}`
- `{{ embeddings[0] }}` → `{"embeddings"}` (still fetched — the template named it)
- static HTML with no `{{` / `{%` → empty set, **no** `get_value`

If python-liquid's public API has no stable variable visitor, implement a small walker on the parsed template in `lynguine` and test it. Do not regex-replace Liquid.

Templates that iterate an undeclared dump (`{% for k, v in vars %}` over the whole mapping) are not used in referia review YAML. If one appears, fallback (F) applies.

### What this CIP does not change

- Pack / explode / gzip IO.
- Compute `row_args` (embeddings stay on the frame for `run_document_distance_analysis`).
- Referia `get_row_data()` / viewer chrome `PopulateButton` (copies the row for widgets and `visible_if`). That is a referia follow-up: widget data should not include packed arrays unless a widget or `visible_if` names them. Note it in referia; do not fork lynguine behaviour there first.
- PlotlyFigure: already field-scoped (CIP-0011 in referia). Keep it that way.

### Alternatives rejected

| Approach | Why not |
|---|---|
| Rewrite 04 YAML to `type: HTML` | Viewer chrome still calls `get_row_data()`; Liquid that needs `store_status` still hits full `mapping()`. YAML cannot opt out of the framework contract. |
| Skip cells larger than N bytes | Implicit. `{{ embeddings }}` would go empty without the template being wrong. |
| Lazy dict / `__getitem__` proxy into `render(**kwargs)` | Liquid may iterate the context; behaviour would depend on the engine. Demand-driven fetch is observable: tests assert which columns were read. |
| `inline_list` vs `side_by_side` | Layout does not choose the Liquid namespace. |

## Implementation Plan

1. **Log hygiene**
   - Remove value interpolation from `mapping()` / `liquid_to_value` debug logs.
   - Test that logging at WARNING does not call `repr` on a large list cell (spy or a cell whose `__repr__` raises).

2. **Subset `mapping(names=...)`**
   - Fetch only requested names; missing names omitted (same as today's unmapped columns, not KeyError unless the name is in the map and the column is absent — keep current error for that case).
   - Existing no-arg `mapping()` tests unchanged.

3. **Template identifier set**
   - Helper `liquid_root_identifiers(source: str) -> set[str]`.
   - Unit tests for the cases in Detailed Description.

4. **`liquid_to_value`**
   - If kwargs omitted: identifiers → `mapping(names=...)` → merge `local` → render.
   - Empty identifier set → render with `local` only.
   - Parse failure → WARNING + full `mapping()`.

5. **Current-index cache**
   - Memoize subset maps; invalidate as in D.
   - Test: two `liquid_to_value` calls naming `store_status` on the same index call `get_value` once.

6. **Referia note (no code in this CIP)**
   - After merge, referia should stop copying packed columns in `get_row_data()` unless widgets/`visible_if` need them. Separate referia CIP.

## Backward Compatibility

- Templates that name a packed column still receive it.
- `mapping()` with no arguments still returns the full dict.
- Jupyter Liquid that mentions only scalar fields becomes faster; results unchanged.
- Templates that relied on *unnamed* columns appearing in the Liquid context (no `{{column}}` but a filter that walks all kwargs) would change. Document as unsupported; fallback (F) covers parse-unknown cases. Add a test that a template mentioning only `title` does not contain `embeddings` in the render context.

No `_referia.yml` changes required for 04_distance. Captions can stay Liquid.

## Testing Strategy

- Unit: identifier extraction (nested path, if, static, named array).
- Unit: `mapping(names=)` vs full `mapping()`.
- Unit: `liquid_to_value` does not `get_value` unmentioned columns (instrument `set_column` / wrap `get_value`).
- Unit: mentioned `embeddings` is still returned.
- Unit: debug logging does not stringify a large cell.
- Unit: cache hit on second Liquid block; miss after `set_value`.
- Regression: existing `tests/test_assess_data.py` mapping tests.

Use a tiny packed-like row (one scalar + one long list) rather than Draghi PDFs.
