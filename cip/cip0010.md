# CIP-0010: Wide flatten — many rows to one row with index-augmented column names

## Summary

Add an explicit **lynguine** reshape that turns a multi-row DataFrame into a **single row** whose column names incorporate the former index values (pandas-style `unstack` + flat MultiIndex names). No parent index is required — unlike lynguine/referia **series** nesting.

This is **not** the referia catalog/events CIP. Hex numbers are per-repository: **lynguine CIP-0010** = this wide-flatten reshape; **referia CIP-0010** (separate repo) = config-driven catalog / events root that consumes CIP-000F directory rows (and may optionally call this reshape). Series hardening remains a further CIP in whichever repo owns that work. Nested vs outer `compute` composition depends on honest phase dispatch — see [CIP-0011](./cip0011.md); do not assume top-level `postcompute` works until that CIP lands or narrows the contract.

**Which requirements does this CIP address?** REQ-0002 (predictable, explicit flow), REQ-0005 (configuration flexibility), REQ-0006 (reshape stays in infrastructure; applications do not invent ad-hoc wide pivots).

**Downstream:** a referia catalog or document flow may opt into this reshape when a directory of configs should appear as **one data point** rather than a browsable multi-row collection. Multi-row catalog browsing does not require this CIP.

## Motivation

Directory allocation (including CIP-000F recursive `yaml_directory` + field projection) correctly produces **one row per file**. Some UIs and documents want the opposite presentation: **one data point** whose fields are the discovered rows, with names that still identify which source each value came from.

Today lynguine has related but different operations:

| Capability | Shape | Parent index? |
|------------|--------|----------------|
| `read_series` | one row; values are **lists** per column | yes (grouped by index) |
| referia series → `entries` | one parent row; nested list-of-dicts | yes |
| `stack` / `hstack` / `vstack` | concatenate **sources** | n/a |
| `CustomDataFrame.pivot_table` | thin pandas wrapper, not a YAML flow step | varies |

None of these implement: **N rows × M columns → 1 row × (N×M) columns**, with names like `{index}{sep}{field}`.

Pandas does this with `unstack` (index → column level) then flattening MultiIndex names (there is no `DataFrame.flatten()`). Lynguine should expose that reshape as an **explicit, documented** flow/assess step so callers do not copy SO one-liners into application code.

## Detailed Description

### Design principles

- **Explicit over magic.** Opt-in config (or named assess op). Default allocation behaviour unchanged.
- **No parent index required.** Unlike series, the result is a solitary wide row (or a trivial single-index frame), not children under a parent key.
- **Names from the index.** Former index values must appear in the new column names (or as a MultiIndex level that is then flattened for Liquid/Excel).
- **Infrastructure stays generic.** No knowledge of `_referia.yml` or catalog UX.
- **Separate from series.** Series (list nesting / writable subseries) needs its own tests and review CIP; this CIP does not harden series save paths.

### Pandas baseline

Idiomatic reshape:

```python
wide = df.unstack().to_frame().T
wide.columns = wide.columns.map(lambda x: separator.join(map(str, x)))
```

Column order depends on MultiIndex level order and optional `sort_index`. Document the chosen default (`index_then_field` vs `field_then_index`) and keep it configurable.

### Configuration sketch

Exact YAML key placement (access post-process vs assess transform vs compute function) is an implementation choice; behaviour should be equivalent to:

```yaml
# Conceptual — after a multi-row input (e.g. yaml_directory)
flatten:
  separator: "_"
  order: index_then_field   # or field_then_index
  columns:                  # optional: subset of fields to widen
    - title
    - date
    - complete
  # index: use current DataFrame index (default)
```

Result for index values `grant/a`, `grant/b` and fields `title`, `complete`:

| grant/a_title | grant/a_complete | grant/b_title | grant/b_complete |
|---------------|------------------|---------------|------------------|
| A             | true             | B             | false            |

### Edge cases (must specify in tests)

- Non-unique index → clear error (cannot unstack unambiguously).
- Empty frame → one empty row or empty columns; pick and document.
- Index values that contain the separator → document escaping or forbid; prefer documenting “separator must not appear in index strings” for v1 unless a safe escape is cheap.
- Non-string index / column names → `str(...)` in the join.
- Optional column subset leaves other columns dropped or kept as globals — document.

### Out of scope

- Referia series → `entries` nesting and writable series Excel save behaviour (separate CIP).
- Catalog UI filters / Liquid `rows` injection (**referia** CIP-0010 — different document/repo; not this CIP).
- Changing CIP-000F discovery semantics.

### Alternatives considered

1. **Series / `entries` without a real parent** — forces a fake parent index; wrong topology for “root is the only point.”
2. **`read_series` lists** — keeps column names but loses per-source scalar fields; poor for templates that want `{{grant_a_title}}`-style names.
3. **Application-side pandas** — works once; violates explicit infrastructure and duplicates policy/tests.
4. **True MultiIndex columns only** — elegant in pandas; awkward for Liquid and Excel mapping. Prefer flatten-to-strings as the default export shape; MultiIndex may be an internal step.

## Implementation Plan

1. **API placement**
   - Decide whether `flatten` is an assess-time DataFrame method, a YAML assess/transform block, a compute registry function, or a thin wrapper around `unstack` on `CustomDataFrame`.
   - Prefer flow-time application after input load (same spirit as other explicit transforms).

2. **Core function**
   - Implement `unstack` + separator join with `order` and optional `columns`.
   - Validate unique index; define empty-frame behaviour.

3. **Wiring**
   - Config schema / docs for the chosen YAML key.
   - Ensure logging names the op and separator for debuggability.

4. **Tests**
   - Unit tests for happy path, order variants, column subset, duplicate index error, empty frame, separator in names policy.

5. **Docs**
   - Short assess/access note + example next to directory allocation examples.
   - Cross-link: “not series; see series CIP when written.”

## Backward Compatibility

Additive only. Existing flows unchanged until they opt into `flatten` (or equivalent). No change to `stack` / `hstack` / `vstack` / `read_series` semantics.

## Testing Strategy

- Pure unit tests on a small fixture DataFrame (no filesystem).
- One integration-style test: multi-row `yaml_directory` (or in-memory frame from CIP-000F-style projection) → flatten → assert column set and single-row values.
- Property: round-trip is not required for v1; document that inverse is `melt`/`stack`-like and out of scope unless requested later.
