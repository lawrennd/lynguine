# CIP-0014: Explode list fields to rows, pack columns to a corpus row, and catalog local PDF/DOCX files

## Summary

Extend CIP-0013 so a flow can (1) catalog local PDF/DOCX paths into a one-row-per-file table, (2) explode a list field into a one-row-per-item table, and (3) pack selected columns of a tall table into **one corpus row of array fields**. Explode and pack are **Access IO** declared in flow / `_referia.yml`, not compute functions and not in-memory frames passed to the next notebook cell.

Addresses [REQ-000D](../requirements/req000D_document-structure-extraction.md) “tabular result with explicit unit identity”. Referia REQ-0010 steps 1–3 and step 6 consume this. Pack is **not** referia compute (that was an earlier CIP-0015 sketch).

## Motivation

`document_segment` returns a list of unit dicts on the current document row. Downstream phrase extract needs **one row per unit**. After extract/embed, subject grain needs the inverse: **one row** whose cells are aligned arrays (`phrases`, `embeddings`, `doc_ids`). Referia compute is row-local (`function(**kwargs)` writing `field` on the current index). It cannot honestly change grain.

pub-dialogue writes `paragraph_chunks.csv` and packs embeddings in Python. Those sidecars are what we replace with declared stores.

## Detailed Description

### Do not reopen CIP-0013

Readers, strategies (`pub_dialogue.v1`, `docx_workshop.v1`, `docx_chatbot.v1`), recogniser, and `document_segment` stay as designed. This CIP adds **catalog**, **explode**, and **pack** around them.

### Stateless contract

Segment still writes `units` onto the document row (cache). Explode **reads that field and writes a new store**. Pack **reads a tall store and writes a one-row store**. No process-global DataFrame. If explode or pack has not been run, the downstream store is absent — the next config fails loudly rather than using leftover memory.

### Not CIP-0010

[CIP-0010](./cip0010.md) wide flatten is N rows × M columns → 1 row × (N×M) **named columns**. Pack here is N rows × K columns → 1 row × K **list/array cells** (the former column values stacked in index order). Different reshape; do not reuse wide-flatten names.

### 1. File catalog

A flow should be able to turn a directory of local files into rows without a hand-maintained roster, while still allowing a hand-written YAML catalog (filename, reader, strategy, metadata).

Proposed Access helper / compute `file_catalog`:

- Parameters (constants): `directory`, `glob` (e.g. `*.pdf`, `*.docx`), optional `reader` inference from suffix (`pdf` / `docx`).
- Writes: rows with `Name` (stem), `filename`, `reader`, `path`. Metadata columns (year, technology, group) stay empty unless the catalog YAML already has them.
- Hand-written `documents.yml` remains valid input; catalog is optional convenience.

Until this lands, referia draft configs use a hand-written `info/documents.yml`.

### 2. Explode list → rows

Declare on the **output** store, because grain changes:

```yaml
input:
  type: yaml
  filename: documents.yml
  index: Name

compute:
  - function: document_segment
    field: units
    row_args:
      path: filename
    args:
      strategy: auto
      aspect: body_chunks

output:
  type: yaml
  filename: chunks.yml
  directory: ../info
  index: unit_id
  explode:
    field: units
    inherit:
      - Name
      - filename
      - reader
      - strategy
      - year
      - technology
      - group
```

Semantics:

- After row-local compute, each input row has `units: [ {unit_id, text, chunk_index, word_count, chunking_method, ...}, ... ]`.
- `output.explode.field` expands that list: one output row per unit dict.
- `inherit` copies parent document columns onto every child row.
- Output index is `unit_id` (must be unique; segmenters already mint ids).
- Unit dict keys become columns (`text`, `chunk_index`, …).

The same clause applies to any list-of-dicts field (referia phrase extract writes `extraction_phrases`, then explode to `phrases.yml`).

Register `units_to_frame` for programmatic callers; the flow path is `output.explode`, not “call units_to_frame and keep the frame”.

### 3. Pack columns → one corpus row

Inverse grain change. Declare a **named output store**, not a compute `function:`:

```yaml
# Tall phrase table is the current output of extract+embed.
# Pack writes a *different* one-row store for grain / distance.
pack:
  type: yaml
  filename: records.yml
  directory: ../info
  index: Name
  pack:
    columns:
      phrases: phrase
      embeddings: embedding
      doc_ids: doc_id
      source_files: filename
    index_value: corpus
```

Semantics:

- Read the tall frame in index order.
- Each `pack.columns` entry stacks that source column into one array cell on the corpus row.
- Alignment is by row order: `phrases[i]`, `embeddings[i]`, `doc_ids[i]` refer to the same phrase.
- `index_value` (default `corpus`) is the single output index.
- Missing embeddings abort the pack with an explicit error (do not silently drop rows unless `drop_incomplete: true` is set).

Do **not** register `pack_corpus_row` in referia (or vongole). Grain and distance then stay ordinary row-local compute on that packed row.

### 4. What this is not

- Not OCR (CIP-0013 out of scope).
- Not CIP-0010 wide flatten.
- Not Assess compute (extract, embed, MPPCA, EMD stay in referia CIP-0015 / CIP-0016, later vongole).
- Not gzip / compressed YAML (lynguine CIP-0015). Packed embedding arrays should use `.yml.gz` once that CIP lands; pack itself does not encode.

### Alternatives rejected

- **Explode or pack as row-local compute returning a DataFrame** — compute registry returns cell values, not a replacement index. Would smuggle a second frame through context.
- **Always explode inside `document_segment`** — breaks CIP-0013’s list-in-one-field contract.
- **Pack inside referia `Compute`** — teaches a grain-changing compute API that vongole would have to invent. Access reshape is the honest home.

## Implementation Plan

1. Specify and test `output.explode` in lynguine IO write path (wide document frame + list field → tall unit frame).
2. Specify and test `pack` write path (tall frame → one row of array columns; alignment tests).
3. Register `units_to_frame` for programmatic callers; document that flows use `output.explode`.
4. Add `file_catalog` (compute or directory reader) with suffix → reader inference.
5. Fixtures: CIP-0013 tiny PDF/DOCX for explode; a three-row phrase table for pack.
6. Referia drafts `01_chunk` and `02_embed` use the clauses (aspirational until implemented).

## Backward Compatibility

- `document_segment` still returns `list[dict]`. Existing list-in-one-field configs unchanged.
- Flows without `output.explode` or `pack` behave as today.
- `segment_pdf_frame` remains as a Python helper.

## Testing Strategy

- Unit: `units_to_frame` empty list, one unit, inherited columns.
- IO: write exploded YAML, read back with `unit_id` index; parent `Name` present on every row.
- Pack: three rows → one row; list lengths equal; order preserved; missing embedding errors.
- Catalog: glob two fake files, inferred readers.
- No live documents beyond CIP-0013 fixtures.
