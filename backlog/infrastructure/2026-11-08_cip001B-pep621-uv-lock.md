# Task: Convert pyproject.toml to PEP 621 and generate uv.lock

> Backlog tasks are DOING the work defined in CIPs (HOW).  
> Implements CIP-001B.

## Description

Replace Poetry-specific packaging metadata with PEP 621 so uv can own the developer lock/install path.

- Move `[tool.poetry]` package metadata to `[project]`
- Move runtime deps to `[project.dependencies]`
- Map extras `documents` / `parquet` to `[project.optional-dependencies]`
- Map Poetry `dev` / `docs` groups to `[dependency-groups]`
- Move `ndlconvert` to `[project.scripts]`
- Switch build backend to hatchling (or the backend chosen in CIP-001B) and preserve YAML data-file includes
- Run `uv lock`, commit `uv.lock`, remove `poetry.lock`
- Confirm `uv sync --extra documents --extra parquet --group dev` and `uv run pytest` / `uv run ruff check lynguine` locally

## Acceptance Criteria

- [x] `pyproject.toml` uses PEP 621 `[project]` (no `[tool.poetry]` packaging tables required for install/build)
- [x] Optional extras `documents` and `parquet` install via standard extras / `uv sync --extra …`
- [x] `dev` and `docs` dependency groups are defined and usable with uv
- [x] `ndlconvert` remains an installed console script
- [x] `uv.lock` is committed; `poetry.lock` is removed
- [x] Local `uv sync` with documents+parquet+dev succeeds
- [x] `uv run pytest` and `uv run ruff check lynguine` succeed on the converted project

## Implementation Notes

Pinned `bibtexparser>=1.4.3,<2` and `pandas>=2.3.0,<3` so uv does not resolve the Poetry `*` wildcards onto breaking majors (bibtexparser 2 / pandas 3). Hatchling includes package YAML without `force-include`.
