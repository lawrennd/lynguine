# Task: Convert pyproject.toml to PEP 621 and generate uv.lock

> Backlog tasks are DOING the work defined in CIPs (HOW).  
> Implements CIP-001B.

## Description

Replace Poetry-specific packaging metadata with PEP 621 so uv can own the developer lock/install path.

- Move `[tool.poetry]` package metadata to `[project]`
- Move runtime deps to `[project.dependencies]`
- Map extras `documents` / `parquet` to `[project.optional-dependencies]`
- Map Poetry `dev` / `docs` groups to `[dependency-groups]`
- Move `ndlconvert` to `[project.scripts]`
- Switch build backend to hatchling (or the backend chosen in CIP-001B) and preserve YAML data-file includes
- Run `uv lock`, commit `uv.lock`, remove `poetry.lock`
- Confirm `uv sync --extra documents --extra parquet --group dev` and `uv run pytest` / `uv run ruff check lynguine` locally

## Acceptance Criteria

- [ ] `pyproject.toml` uses PEP 621 `[project]` (no `[tool.poetry]` packaging tables required for install/build)
- [ ] Optional extras `documents` and `parquet` install via standard extras / `uv sync --extra …`
- [ ] `dev` and `docs` dependency groups are defined and usable with uv
- [ ] `ndlconvert` remains an installed console script
- [ ] `uv.lock` is committed; `poetry.lock` is removed
- [ ] Local `uv sync` with documents+parquet+dev succeeds
- [ ] `uv run pytest` and `uv run ruff check lynguine` succeed on the converted project

## Implementation Notes

Preserve constraint intent from today’s Poetry deps (including lower bounds such as `numpy>=2`, `pyzmq>=26`, `cryptography>=50`, and the pyarrow range). Prefer hatchling unless implementation finds a blocking reason; document the choice in the CIP progress notes if it changes.

Do not change library runtime behaviour — packaging metadata only.
